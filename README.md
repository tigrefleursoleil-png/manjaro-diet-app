# クリニック向け 患者質問対応AIチャットボット

**ホームページの内容を読み込んで**、患者さんからの質問にキャラクターが会話形式で自動回答するAIボットです。
回答の根拠はホームページに書かれていることだけ。診療科や取り扱い内容をコードに書き込んでいないので、
**ホームページを更新すれば回答もそれに追従します**。
埋め込みは**スクリプト1行**。右下にキャラクターのボタンが出ます。

```
ホームページ                     このアプリ                     Claude API
┌──────────────┐   ①巡回   ┌─────────────────┐            ┌──────────┐
│ /price /faq… │◀─────────│ クローラ         │            │          │
│              │           │  ↓ 本文を分割    │            │ Opus 5   │
│  [👩‍⚕️ボタン] │           │ 検索インデックス │            │          │
│      ↓       │  ②質問    │  ↓ 関連箇所を抽出│  ③資料+質問 │          │
│  チャット欄  │──────────▶│ キャラ設定+安全ルール ───────▶│          │
│              │◀──────────│ ◀── 回答をストリーム配信 ─────│          │
└──────────────┘  ④回答    └─────────────────┘            └──────────┘
```

## 1. できること

| | 内容 |
|---|---|
| 👩‍⚕️ 埋め込みボタン | `<script>` 1行で右下に女性医師キャラクターのボタン。既存ボタンから `ManjaroChat.open()` でも起動 |
| 💬 会話形式 | キャラクター「あおい」（やさしい女性医師の姿をしたAI案内役）が丁寧語で回答。吹き出し・タイピング表示つき |
| 🔄 最新情報を維持 | ホームページを定期巡回（既定6時間ごと）。料金改定・新しいFAQ・診療内容の追加を自動で反映し、更新時刻を画面に表示 |
| 🎯 サイト任せの設計 | 診療科・病名・治療名をコードに持たない。質問ボタンもホームページのページ構成から自動生成 |
| 🔗 出典表示 | 回答の下に根拠ページへのリンクを最大3件表示 |
| 🩺 医療上の安全設計 | 診断・処方指示・検査結果の解釈を禁止、記載のない数値は答えない、危険な症状は即受診・救急案内（AIを介さず定型文） |
| 📝 相談ログ | 質問と回答を `data/conversations.jsonl` に記録（FAQ改善用。氏名等は尋ねません） |

## 2. セットアップ

```bash
npm install
cp .env.example .env      # ANTHROPIC_API_KEY と SITE_URL を記入
npm run crawl             # ホームページを取り込む（初回のみ手動でも可）
npm run dev               # http://localhost:8787/demo.html で動作確認
```

`.env` の最低限の設定:

```bash
ANTHROPIC_API_KEY=sk-ant-...            # https://console.anthropic.com で発行
SITE_URL=https://あなたのホームページ    # ここを起点に同一ドメイン内を巡回
ALLOWED_ORIGINS=https://あなたのホームページ
```

本番:

```bash
npm run build && npm start
```

### 動作確認用コマンド

```bash
npm run crawl                              # いま何ページ取り込めるか確認
npm run search -- "駐車場" "予約は必要ですか"       # 検索が効いているか（APIキー不要）
npm run ask    -- "初診の流れを教えて"              # 実際の回答を確認（APIキー必要）
```

## 3. ホームページへの埋め込み

`</body>` の直前に1行貼るだけです。

```html
<script src="https://chat.example.clinic/widget/manjaro-chat.js"
        data-api="https://chat.example.clinic" defer></script>
```

| 属性 | 説明 |
|---|---|
| `data-api` | このアプリのURL。ウィジェットを同じサーバーから配信する場合は省略可 |
| `data-position` | `right`（既定）/ `left` |
| `data-teaser` | `off` で「話しかけ吹き出し」の自動表示をオフ |

ページ内の任意のボタンから開く場合:

```html
<button onclick="ManjaroChat.open()">AIに質問する</button>
<button onclick="ManjaroChat.ask('初診の流れを教えて')">初診について聞く</button>
```

`ManjaroChat.open() / close() / toggle() / reset() / ask(text)` が使えます。
URL末尾に `#chat` を付けてアクセスすると、開いた状態で表示されます。

Shadow DOM で描画しているため、ホームページ側のCSSと干渉しません（WordPress・STUDIO・Wix などでも同様に貼れます）。

## 4. キャラクターと文言のカスタマイズ

すべて `config/site.json` で変更できます（コード修正は不要）。

- `character.name` / `title` / `greeting` … キャラクター名（既定「あおい」）・肩書き・最初のあいさつ
- `character.personality` / `speechStyle` … 性格と話し方（そのままシステムプロンプトに反映）
- `character.suggestions` … 最初に出す質問ボタン。**空 `[]` にしておくと、取り込んだホームページのページ構成から自動生成します**（例:「費用について」というページがあれば「費用について教えて」）
- `character.theme` … 配色。`avatarUrl` に画像URLを入れると、既定の女医イラスト（インラインSVG）の代わりにその画像を使います。院内で撮影した写真や、描き起こしたキャラクターに差し替えられます
- `clinic` … 医院名・診療時間・電話・予約/問い合わせURL（回答内の案内先になります）
- `policy.disclaimer` … 画面下部に常時表示する免責文

診療科ごとの言い換え（例:「舌下免疫療法」＝「減感作」）を検索に足したいときは、
`config/synonyms.example.json` を `config/synonyms.json` にコピーして書き足してください（任意）。

変更後はサーバーを再起動してください。

## 5. 最新情報の取り込み（クローラ）

- `SITE_URL` を起点に、`sitemap.xml` があればそれを優先、無ければ同一ドメインのリンクを辿ります
- `robots.txt` の `Disallow` を尊重し、画像・PDF・CSS等は取得しません
- 本文は `main` / `article` などの領域だけを抽出し、ナビ・フッター・スクリプトは除外。表やリストは区切りを保ったまま平文化するので料金表も読み取れます
- 見出し単位に分割して検索インデックス（日本語向けBM25。形態素解析器なしで動作）を作成
- 同一内容の重複URL（`/` と `/index.html` など）は1つにまとめます
- `CRAWL_INTERVAL_MINUTES`（既定360分）ごとに自動再取得。内容が変わったページは `changedUrls` に記録され、`/api/status` で確認できます

手動更新（`ADMIN_TOKEN` を設定している場合）:

```bash
curl -X POST https://chat.example.clinic/api/admin/refresh -H "x-admin-token: $ADMIN_TOKEN"
```

検査料金の改定などを即座に反映したいときは、CMS の更新後にこのURLを叩いてください。

## 6. 医療上の安全設計

医療機関のサイトに置く前提で、次の制御を入れています。

**モデルに渡す前（コード側で機械的に判断）**
- 診療科を問わない危険サイン（息苦しさ・胸痛・意識障害・けいれん・大量出血・激しい痛み・ろれつが回らない・薬の誤飲・高熱でぐったり・アナフィラキシーを疑う症状など）を検出したら、**AIを呼ばずに**受診/救急案内の定型文を返す
- 「〜とはどんな症状ですか」のような説明を求める質問は緊急扱いにせず、通常どおり回答する
- 危険サインの一覧は `src/chat/safety.ts` の `EMERGENCY` にまとまっています。医院の診療内容に合わせて足し引きできます
- 「死にたい」等の訴えは相談窓口（こころの健康相談統一ダイヤル・いのちの電話・119）を案内
- 質問は1,000文字までに制限、制御文字を除去、IPごとに毎分12回まで

**システムプロンプト（`src/chat/persona.ts`）**
- 医師ではなくAIの案内役であることを明示（聞かれたら正直に答える／「先生」とは名乗らない）
- 診断しない／原因や病名を断定しない／検査結果を解釈しない／処方・薬の変更を指示しない
- 治療の適応・可否（受けられるか、やめてよいか）を判断せず、診察が必要と伝える
- **ホームページに書かれていない数値（費用・年齢・期間・回数）は答えない**。推測や一般論での穴埋めを禁止
- お子さん・妊娠中・授乳中・持病がある方は一般情報にとどめ、必ず医師相談へ案内
- 個人情報を尋ねない・復唱しない
- 該当情報がない場合は正直に伝え、問い合わせ先を案内

**画面**
- 免責文（`policy.disclaimer`）を入力欄の下に常時表示
- 回答の根拠ページへのリンクを表示し、患者さんが原文を確認できる

> 実運用の前に、想定質問（費用・予約方法・診療時間・受診年齢・症状が出ているときの対応など）を
> `npm run ask` で通し、医師の確認を受けてから公開してください。医療広告ガイドラインに関わる表現は
> `config/site.json` と `src/chat/persona.ts` で調整できます。

## 7. API

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/config` | キャラクター設定・あいさつ・サジェスト・知識ベース更新時刻（ウィジェットが使用） |
| POST | `/api/chat` | 質問。`{sessionId, message}` を送り、SSE（`sources` / `delta` / `done`）で回答が届く |
| POST | `/api/chat/reset` | 会話履歴のリセット |
| GET | `/api/status` | モデル・セッション数・知識ベースの状態・直近クロール結果 |
| POST | `/api/admin/refresh` | 手動再クロール（`x-admin-token` ヘッダー必須） |

会話履歴はサーバーのメモリに最大12往復・2時間だけ保持し、ディスクには保存しません
（相談内容の記録は `LOG_CONVERSATIONS=false` で完全に無効化できます）。

## 8. 本番運用の注意

- **HTTPS 必須**、`ALLOWED_ORIGINS` は `*` にせず本番ドメインを明記してください
- リバースプロキシ経由の場合、SSEのバッファリングを切ってください（nginx: `proxy_buffering off;`。`X-Accel-Buffering: no` は送信済み）
- プロセス常駐は systemd / PM2 / Docker などお好みで。`data/` に知識ベースとログが入るので永続ボリュームにしてください
- 複数プロセスで動かす場合、会話履歴はプロセスごとに分かれます（同一プロセスに固定するか、履歴を外部ストアへ移してください）
- モデルは `BOT_MODEL` で変更可（既定 `claude-opus-5`）。`BOT_EFFORT` は応答の丁寧さと速度・費用のバランス調整（既定 `low`）
- 費用の目安は **1質問あたり数円程度**（システムプロンプトはプロンプトキャッシュに載るため、連続する質問ほど安くなります）。正確な数値は `/api/status` とAPIの利用状況で確認してください

## 9. 構成

```
config/site.json          医院情報・キャラクター設定・免責文（ここを編集すれば運用できます）
config/synonyms.json      任意。診療科ごとの言い換え辞書（example をコピーして使用）
src/
  server.ts               Express サーバー（API・SSE・静的配信・定期クロール）
  config.ts               .env と site.json の読み込み
  kb/
    crawler.ts            sitemap/リンク巡回・robots対応・差分検出
    extract.ts            HTML→本文抽出・見出し単位のチャンク化
    search.ts             日本語BM25検索（CJK2文字グラム＋類義語展開）
    knowledge.ts          知識ベースとインデックスの保持・再構築・質問ボタンの自動生成
    store.ts              data/knowledge.json の読み書き
  chat/
    persona.ts            キャラクター設定＋医療ルールのシステムプロンプト
    safety.ts             危険サイン（診療科共通）・危機的訴えの事前検出
    chat.ts               検索→Claude呼び出し→ストリーム返却・会話履歴
  cli/                    crawl / ask / testsearch（動作確認用）
widget/manjaro-chat.js    埋め込みウィジェット（Shadow DOM・SSE受信・キャラクターSVG）
public/demo.html          埋め込みデモページ
```

## 10. 現状の確認済み範囲

- クロール → 抽出 → 検索 → SSE配信 → ウィジェット表示までを、ローカルのテスト用サイト（内科・小児科・皮膚科・アレルギー科・健診をもつ総合クリニック）で通しで確認済み。
  「駐車場はありますか」「子どもは何歳から」「予防接種の値段」「薬だけもらえますか」「紹介状は書いてもらえる？」「土曜は何時まで」がいずれも正しいページを引けています
- 質問ボタンがホームページのページ構成から自動生成されること（「診療科について教えて」「費用について教えて」「アクセスについて教えて」）を確認済み
- 危険サイン判定は14パターンのテストで期待どおり（胸痛・けいれん・吐血・誤飲などは緊急、通常の問い合わせは通常回答）
- レート制限、400/429、管理APIの認証、会話リセット、PC/スマホ表示、Chromiumでのコンソールエラーなしを確認済み
- キャラクターのSVGは 220px / 96px / 46px / 30px / 22px で描画確認済み（小さいサイズでも女性医師と分かる形）
- **Claude API を実際に呼び出す部分は未検証**です（この開発環境にAPIキーがないため）。`ANTHROPIC_API_KEY` を設定して `npm run ask -- "初診の費用はいくらですか？"` を実行すると、実際の回答と使用トークン数が確認できます。キー未設定時は、AI応答の代わりに問い合わせ先の案内が返ります

> ファイル名・グローバル変数名（`widget/manjaro-chat.js` / `ManjaroChat`）はリポジトリ名に合わせて据え置きです。`clinic-chat.js` / `ClinicChat` などへ改名した方がよければお知らせください。
